# R2V 三任务标注分歧分析 Agent 设计规格

日期：2026-07-31  
状态：已确认方向，待实施  
适用任务：物品、场景、音频

## 1. 产品目标

将现有的通用表格可视化工具升级为面向 R2V 标注业务的数据分析 Agent。用户上传导出的 Excel、CSV 或 TSV 后，系统直接识别数据结构并完成分析，不再要求用户逐项确认字段。

产品最重要的目标不是展示常规行数、空值和趋势，而是回答以下业务问题：

1. 哪些标注维度经常产生分歧？
2. 哪些具体题目最需要拿出来对齐？
3. 同一道题的同一维度，标注员分别选择了什么？
4. YES、NO、高度相似、低相似等不同答案背后的原因是什么？
5. 总分与维度答案之间是否存在明显规则冲突？
6. 是否存在答案缺失、REF 数组错位、分组非法等提交质量问题？
7. 哪些标注员经常偏离多数判断，需要进一步抽检？

## 2. 设计原则

### 2.1 无阻断自动识别

上传后直接分析，不展示“字段确认”弹窗，不要求用户逐项选择题目 ID、标注员或维度字段。

自动识别结果在页面的“数据口径”抽屉中可查看，包括：

- 识别出的任务类型
- 用于聚合同一道题的字段
- 标注员字段
- 完成状态判断
- 识别出的 REF 槽位
- 识别出的总分、维度、原因和分组字段

若识别置信度不足，系统采用优先级规则和内容特征作出最佳判断，并在结果页给出非阻断提示。用户可以手动切换“物品 / 场景 / 音频”，但不需要重新映射全部字段。

### 2.2 三套规则独立

物品、场景和音频分别使用独立的：

- 答案选项
- 分数体系
- 维度集合
- 原因字段要求
- REF 与分组逻辑
- 价值评分规则
- 规则冲突检查

三类任务不得直接混用分数或答案语义。

### 2.3 先保留原始答案，再做规范化

系统同时保留：

- 原始字段名
- 原始答案文本
- 规范化后的任务、REF、维度、答案和原因

规范化只用于聚合，不覆盖原始数据。用户可以从任意图表下钻回具体题目、标注员和原始答案。

### 2.4 分歧不等于错误

系统默认描述为“分歧”“低共识”“规则疑似冲突”，不直接把少数答案判定为错误。

只有以下情况可以标记为确定性数据问题：

- 缺少模板要求的必填字段
- 答案不属于允许的枚举
- REF 数组与实际 REF 槽位错位
- 同一个 REF 加入多个互斥分组
- 分组人数或成员数量违反模板规则
- 已开始填写的必填组未填写完整

总分与维度语义不一致属于“规则疑似冲突”，供 POC 复核。

## 3. 输入识别与规范化

## 3.1 支持格式

- `.xlsx`
- `.xls`
- `.csv`
- `.tsv`

浏览器本地解析，原始文件不上传服务器。

## 3.2 任务类型自动识别

识别优先级：

1. JSON 答案键名
2. 展平后的列名
3. 维度答案内容
4. 文件名、任务名等辅助信息

典型识别特征：

- 音频：`refToneConsistency`、`refDialectConsistency`、`refEnvironmentConsistency`、`targetClarityIntegrity`
- 场景：空间布局、场景锚点、视角、场景状态、主体构成、场景覆盖度、场景组
- 物品：`consistencyDimensions`、文字图案、材质、颜色、镜头、主体覆盖度、对象价值、多视图价值

如果一张表包含多个任务类型，按行识别后分别生成任务分区，不把不同任务混合统计。

## 3.3 同一道题的聚合键

系统需要区分“平台分配记录 ID”和“同一道底层题目的 ID”。

聚合键优先级：

1. `uid`
2. `orig_uid`
3. `数据标识`
4. `object_id`
5. `name`
6. `target_video + ref_1 ... ref_6` 的稳定本地哈希

`题目ID`、assignment ID 或每位标注员独有的提交 ID，若唯一率接近 100%，不得直接用于聚合同一道题。

页面在“数据口径”中说明最终采用的聚合键，但不要求用户确认。

## 3.4 标注员识别

优先识别：

- `[标注]操作人`
- 标注员
- 操作人
- annotator
- worker
- user

若没有标注员字段，仍生成题目和维度分析，但隐藏标注员偏差模块。

## 3.5 完成记录识别

完成记录优先依据：

1. `最终结果-JSON` 非空且可解析
2. `答案` 非空且可解析
3. 存在核心总分或维度答案
4. 明确的完成状态字段

未完成记录不进入分歧率分母，但必须进入“完成覆盖”统计。页面同时显示：

- 总分配记录数
- 已完成记录数
- 未完成记录数
- 完成题目数
- 每题有效标注人数分布

## 3.6 JSON 与展平字段兼容

系统同时支持：

- 一列完整答案 JSON
- 平台已展平的 `[标注]...` 列
- 两者同时存在

当两者同时存在时：

1. 使用 JSON 建立完整结构
2. 使用展平列补充可读列名
3. 对两者不一致的记录给出“答案源不一致”提示

## 3.7 REF 槽位

- 固定保留 `ref_1` 至 `ref_6` 的槽位编号
- 空槽位不得导致后续 REF 前移
- 所有 REF 数组下标遵循：`ref_1 → 0`，`ref_2 → 1`，依此类推
- 分析单位必须包含 REF 槽位，不能把同一道题的多个 REF 混成一个答案

规范化的最小分析单位：

`任务类型 × 题目 × REF/分组 × 维度 × 标注员`

## 4. 通用分歧指标

## 4.1 单元格定义

“题目维度单元格”指同一道题、同一个 REF 或分组、同一个维度下的全部有效标注答案。

至少有 2 个有效答案时才计算分歧。只有 1 个有效答案时显示结果，但标记为“样本不足”。

## 4.2 一致率

`一致率 = 该单元格中人数最多的答案人数 ÷ 有效标注人数`

示例：7 人 YES、3 人 NO，一致率为 70%。

## 4.3 分歧度

`分歧度 = 1 - 一致率`

示例：7 人 YES、3 人 NO，分歧度为 30%。

## 4.4 分歧发生率

在某个维度下：

`分歧发生率 = 出现两个及以上答案的题目维度单元格数 ÷ 有效题目维度单元格数`

该指标回答“这个维度有多少题发生过分歧”。

## 4.5 严重分歧率

默认规则：

`严重分歧 = 一致率 ≤ 60%`

`严重分歧率 = 严重分歧单元格数 ÷ 有效单元格数`

页面允许查看阈值为 50%、60%、70% 时的结果，但默认使用 60%。

## 4.6 答案混乱度

使用规范化熵区分：

- 两派分歧
- 多档答案均有人选择
- 答案高度集中

对于二元维度，7:3 与 5:5 可以区分强弱；对于音频四档维度，可以识别 YES、高度相似、低相似、无法判断同时出现的“千奇百怪”题目。

## 4.7 总分分歧

总分单独分析：

- 众数
- 一致率
- 分歧度
- 最大最小跨度
- 分数分布
- 严重跨档分歧

音频总分顺序为 `0 < 1 < 3 < 5`；物品和场景为 `0～5`。物品的 `SKIP/不打分` 单独统计，不当作数值 0。

## 5. 原因汇总

## 5.1 按答案分组

原因必须与答案绑定展示，例如：

- 材质一致性 / YES 的常见原因
- 材质一致性 / NO 的常见原因
- 音色一致 / 高度相似的常见原因
- 音色一致 / 低相似的常见原因

不得把相反选项的理由混在一个词云或摘要里。

## 5.2 汇总输出

每个“任务 × 维度 × 答案”输出：

- 原因记录数
- 高频关键词或短语
- 相似原因簇
- 每个原因簇的占比
- 代表性原始原因
- 涉及的题目数

系统不编造原因。当模板不收集该维度原因时，明确显示“该维度不收集原因”。

## 6. 音频任务规则

## 6.1 REF 展示与数组

- 默认存在 `ref_1`
- `ref_2` 至 `ref_6` 只有在数据中实际存在时才参与分析
- REF 相关答案均按数组下标与固定槽位对应
- 缺失槽位不重排

## 6.2 一致性总分

每个 REF 独立评价：

- 0：不可用或完全不匹配
- 1：低相似
- 3：高度相似
- 5：完全一致

## 6.3 一致性维度

通用一致性：

- Yes
- No
- 无法判断

其他六个维度：

- Yes
- 高度相似
- 低相似
- 无法判断

维度包括：

1. 音色一致
2. 方言语种吐字归音习惯一致
3. 情绪一致
4. 风格语调一致
5. 环境声场一致
6. 应用场景一致

一致性原因中，只有“音色一致”收集必填原因。其余六个一致性维度不应因缺少原因被判为数据缺失。

## 6.4 价值评分

Target 与每个实际存在的 REF 均独立记录：

- 价值总分：高 / 中 / 低
- 音频清晰与完整：Yes / No
- 音频情绪波动与起伏：Yes / No
- 两个价值维度对应原因

当前模板要求 Target 和每个 REF 都填写两个价值维度及原因。因此数据完整性检查以模板实际字段为准。

规则文档中“REF 价值主要关注清晰完整”的业务口径用于解释价值总分，但不忽略模板已经收集的 REF 情绪字段。

## 6.5 音频规则疑似冲突

以下组合进入复核清单：

- 5 分但通用一致性不是 Yes
- 5 分但任一核心维度为低相似或无法判断
- 3 分但音色不是 Yes/高度相似
- 3 分但通用一致性为 Yes，可能更接近同源音频
- 1 分但音色为 Yes 且多数其他维度高度一致
- 0 分但核心维度大量选择 Yes
- 音色明显不一致但总分超过业务封顶
- 价值总分与清晰完整、情绪起伏组合明显冲突

这些规则只标记“疑似冲突”，不自动判错。

## 7. 场景任务规则

## 7.1 REF 规则

- 最多 6 个固定 REF 槽位
- 空槽位不重排
- 没有 REF 属于输入异常
- 超过 6 个 REF 属于输入异常
- 只有 1 个 REF 时，不应要求多视图一致性
- 2～6 个 REF 时，允许多视图一致性

## 7.2 单 REF 一致性

每个实际 REF：

- 总分：0～5
- 六个维度
- 每个维度对应原因

六个维度：

1. 空间与布局一致性
2. 场景锚点一致性
3. 视角一致性
4. 场景状态一致性
5. 主体构成一致性
6. 场景覆盖度

主体构成一致性允许：

- YES
- NO
- N/A

其他维度只允许 YES / NO。

## 7.3 多视图一致性

- 整体选做
- 如果某个组已经开始填写，则该组必须完整
- 每组包含若干 REF
- 每组需要 0～5 分
- 每组需要六个维度及原因

## 7.4 场景价值

- 场景价值性必做
- 至少 1 个场景组
- 每组选择若干 REF
- 每组分数为 0～2
- 每组填写原因

## 7.5 场景规则疑似冲突

结合 3.0 规则文档检查：

- 5 分但空间布局、锚点、视角或状态存在 NO
- 4 分但除主体构成外存在明显核心差异
- 3 分但视角一致，且其他维度也全部一致
- 2 分但空间布局为 NO
- 0 分或 1 分但所有核心维度均为 YES
- 场景价值高分但没有新增视角、空间关系或增量信息的理由

## 8. 物品任务规则

## 8.1 单 REF 一致性总分

- 0：物品未出现、完全不同类或无有效物品
- 1：同类但不同款
- 2：同款但不是同一个物品
- 3：同款同一个物品，但受环境、光线、角度等影响
- 4：同一个物品处于不同环境，整体高度一致
- 5：完全一致，关键帧或近似关键帧
- SKIP/不打分：多主体等无法正常评价

## 8.2 单 REF 一致性维度

1. 形状一致性
2. 文字图案一致性
3. 材质一致性
4. 颜色一致性
5. 镜头一致性
6. 场景一致性
7. 主体覆盖度

普通维度为 YES / NO；场景一致性允许 YES / NO / 不考虑。正常评分时，每个维度都必须有原因；SKIP 可以跳过。

## 8.3 多视图组

- 每组至少 2 个 REF
- 同一个 REF 不能加入多个组
- SKIP 或多主体 REF 不应入组
- 每组需要 0～5 分、七个维度和原因
- 分组成员变化后，旧的价值答案不能继续与新成员混用

## 8.4 对象价值

评分对象：

- 未入组的单个 REF
- 已建立的多视图对象组

总分：

- 0
- 1
- 2
- SKIP/不打分

维度：

1. 文字与包装信息
2. 复杂图案
3. 复杂纹理
4. 精细结构
5. 精细工艺复杂纹理
6. 主体清晰度

正常评分要求全部维度和原因；SKIP 可以跳过。价值遵循 Target 与 REF 两侧取较低值的原则。

## 8.5 物品规则疑似冲突

- 5 分但任一关键维度为 NO
- 4 分但形状、文字图案或材质存在明显不一致
- 2 分或以下但全部关键维度为 YES
- SKIP 仍填写并参与了多视图组
- 价值 2 分但主体清晰度为 NO
- 价值 2 分且精细信息维度全部为 NO
- 单 REF 已入组但仍存在独立价值答案
- 分组成员改变后仍保留旧价值答案

## 9. 分析页面

## 9.1 上传与即时结果

上传文件后直接进入结果页，页面顶部显示：

- 自动识别的任务类型
- 总记录数
- 已完成记录数
- 底层题目数
- 平均每题标注人数
- 高分歧题目数
- 规则疑似冲突数

任务类型旁提供非阻断的手动切换入口。

## 9.2 维度视角

按维度排序展示：

- 分歧发生率
- 平均分歧度
- 严重分歧率
- 平均一致率
- 平均混乱度
- 有效题目数
- 主要答案分布

默认按严重分歧率和平均分歧度综合排序。

## 9.3 题目视角

每道题展示：

- 有效标注人数
- 发生分歧的维度数
- 严重分歧维度数
- 总分分歧
- 平均一致率
- 最高混乱度
- 规则疑似冲突数
- 是否样本不足

支持从最值得对齐的题目向下排序。

## 9.4 题目 × 维度热力图

颜色表示分歧度或一致率。点击单元格展开：

- 答案人数与比例
- 每位标注员答案
- 按答案分组的原因
- 原始题目和 REF 槽位
- 总分与维度关系

## 9.5 原因视角

按任务、维度和答案切换，展示高频原因、相似原因簇和代表题目。

## 9.6 规则冲突视角

分为：

- 确定性提交问题
- 总分与维度疑似冲突
- 价值总分与价值维度疑似冲突
- 分组与数组结构问题

每条问题可下钻到题目、REF、标注员和原始字段。

## 9.7 标注员视角

在存在标注员字段时展示：

- 有效提交数
- 与题目多数答案的一致比例
- 各维度偏离率
- 高频选择倾向
- 无法判断使用率
- 规则疑似冲突数

标注员偏离只作为抽检线索，不直接作为能力结论。

## 9.8 完成覆盖视角

单独展示：

- 每题有效人数分布
- 少于预期标注人数的题目
- 完成率
- JSON 解析失败
- 必填字段缺失
- REF 数组长度错位
- 无效枚举

完成度问题不混入分歧率。

## 10. 输出

支持导出：

1. 完整分析报告 Markdown
2. 维度分歧明细 CSV
3. 题目风险清单 CSV
4. 原因汇总 CSV
5. 规则冲突清单 CSV
6. 标注员抽检建议 CSV

所有导出都包含分析口径、有效样本数和生成时间。

## 11. 当前音频样例回归基线

样例文件：

`7668287611890323236_20260731113204.csv`

已知结构：

- 2,700 条平台分配记录
- 448 条有完整答案的提交
- 50 道底层题目
- 每题有效标注人数为 8～10 人
- `题目ID` 是分配记录 ID，不用于聚合同一道题
- 优先使用 `uid` 聚合
- 标注员字段为 `[标注]操作人`
- 任务类型为音频
- 维度选项包含 YES、HIGH_SIMILARITY、LOW_SIMILARITY、UNKNOWN

升级后的结果必须稳定识别上述结构，并且不得再次把 2,700 条记录当成 2,700 道题。

## 12. 验收标准

1. 上传三类任一模板导出表后，不出现字段确认流程。
2. 自动识别任务类型、底层题目、标注员、REF 槽位和答案字段。
3. 多 REF 不错位、不合并。
4. 音频、场景、物品使用各自的选项和分数体系。
5. 分歧率能按维度和单题两种方向统计。
6. 7 人 YES、3 人 NO 的一致率为 70%，分歧度为 30%，并判定为发生分歧。
7. 四档答案可以计算混乱度。
