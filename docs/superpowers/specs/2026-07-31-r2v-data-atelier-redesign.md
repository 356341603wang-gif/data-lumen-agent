# R2V Data Atelier 界面重设计说明

日期：2026-07-31

## 1. 目标

在不改变 R2V 分析能力、数据口径和上传流程的前提下，彻底重做视觉层与关键交互。

新版需要解决当前界面的三个问题：

1. 视觉过于扁平，像常见的质检后台，缺少品牌记忆点。
2. 内容密度虽然高，但层级差异不足，用户难以快速判断“先看什么”。
3. 上传页与分析页像两个独立产品，没有贯穿始终的视觉语言。

最终体验应当保留上一版 Data Lumen 的高级感，同时比上一版更适合展示复杂的标注分歧证据。

## 2. 设计方向

方向名称：Data Atelier / 数据工坊

整体气质是“研究工作台与编辑式数据报告的结合”。界面不是传统后台，也不是炫技式大屏，而是一张有空间、有重点、可以逐层展开的分析桌面。

核心视觉要素：

- 暖灰网格画布，恢复上一版的纸张感和空间感。
- 黑色核心工作区，用于上传入口、关键结论和高优先级证据。
- 荧光绿作为唯一主信号色，只用于行动按钮、当前状态、关键指标和证据轨迹。
- 大字号、紧凑字距、不对称布局，避免规整卡片阵列带来的模板感。
- 少量宋体斜体只用于标题中的关键词，形成中文排版记忆点。
- 图标统一使用 Lucide 线性图标，保持相同描边粗细。

基础色：

- Paper：`#F1F0EA`
- Surface：`#FAF9F4`
- Ink：`#10110F`
- Muted：`#6F716A`
- Line：`#D7D7CF`
- Acid：`#B9F52B`
- Acid Dark：`#6FA600`
- Warning：`#F1A73B`
- Danger：`#EE6B55`

字体：

- 大标题：`Avenir Next Condensed` / `DIN Condensed` / `PingFang SC`
- 正文与界面：`Avenir Next` / `PingFang SC`
- 数据与编号：`SFMono-Regular` / `ui-monospace`
- 中文强调：`Songti SC`

不依赖在线字体，保证国内和外部网络都能稳定显示。

## 3. 视觉记忆点

主记忆点称为“证据轨道”。

从总览中的结论出发，一条细荧光绿轨道贯穿结论、指标、答案分布和原因证据。用户进入维度榜、单题榜或热力图后，当前选中的证据会沿同一轨道展开到右侧详情抽屉。

这不是装饰线，而是用于表达：

`结论 → 分歧数值 → 人员答案 → 原因证据`

上传页中的圆形轨道动画与分析页的证据轨道使用同一种视觉语言，使两页属于同一个产品。

## 4. 上传页

### 4.1 页面结构

桌面端使用不对称双栏：

- 左侧约 56%，展示超大标题、产品说明与四类核心分析能力。
- 右侧约 44%，放置黑色上传工作台。

暖灰背景保留 40px 网格纹理。顶部导航半透明但不使用廉价玻璃效果，只做轻微背景模糊和细线分隔。

### 4.2 上传工作台

上传区域恢复上一版的黑色主卡片：

- 高度约 600px，具备充足留白。
- 右上角有两层低透明度圆形轨道。
- 中部上传图标被动态轨道包围。
- 拖入文件时，卡片整体轻微上浮，荧光绿描边出现。
- “选择文件”为荧光绿主按钮。
- “查看音频示例”为低强调文字按钮。
- 隐私说明固定在卡片底部，不与主要操作抢层级。

### 4.3 动效

- 页面进入时：标题分行向上揭示，上传卡片从右侧轻微滑入。
- 上传轨道持续低速旋转，不依赖鼠标。
- 拖拽文件时：轨道加速一次，随后恢复。
- 动画必须支持 `prefers-reduced-motion`。

## 5. 分析工作台

### 5.1 整体布局

分析页使用固定顶部操作栏、左侧窄导航和右侧内容画布。

- 顶部栏：文件名、任务类型、复制、导出、换文件。
- 左侧导航：保留 8 种分析方式，但改为更精炼的编号导航。
- 内容区：不再使用同尺寸白卡片铺满，而是根据结论优先级形成不对称 Bento 布局。

画布背景延续暖灰网格。内容模块使用浅色纸面、黑色主结论板和局部荧光绿信号。

### 5.2 总览首屏

总览首屏分为三层：

1. 顶部摘要：有效标注、题目数、高分歧题、确定性问题。
2. 左侧黑色“本批最需要对齐”结论板，展示第一优先结论。
3. 右侧交错排列其他结论与关键答案分布。

首页进入后，用户无需滚动就能回答：

- 哪个维度最需要关注？
- 哪道题最值得拿出来对齐？
- 是严重分歧还是普通少数意见？
- 当前数据是否存在完成覆盖问题？

### 5.3 榜单

维度榜和单题榜采用编辑式排名：

- 排名数字作为版式元素，而不是单独的小标签。
- 每行同时显示分歧率、严重分歧率、混乱度和有效样本。
- 前三名有不同的信息层级，但不使用金银铜奖牌。
- 点击一行后，证据抽屉从右侧展开。

### 5.4 热力图

热力图保留现有计算逻辑，重做视觉表现：

- 单元格不是纯红色深浅，而是从纸面灰、酸绿提示、橙色争议到红色严重分歧。
- 左侧题目列固定，顶部维度名可横向滚动。
- 悬停或点按时显示人数分布与严重分歧判断。
- 点击后进入证据抽屉，不能只显示一个百分比。

### 5.5 原因、冲突、标注员和覆盖

- 原因汇总按答案立场分栏展示，避免把 YES 与 NO 的原因混在一起。
- 规则冲突分为“确定性问题”和“业务复核”，视觉级别明确区分。
- 标注员偏差使用离群轨迹而不是普通进度条。
- 完成覆盖保持独立页面，避免把缺失记录错误计算为分歧。

## 6. 证据抽屉

证据抽屉是整个分析页的核心交互。

抽屉包含：

1. 当前题目、REF 与维度。
2. 一致率、分歧率、混乱度和有效人数。
3. 答案分布。
4. 标注员及其选择。
5. 按答案分别整理的原因。

抽屉宽度桌面端约 480px；移动端使用底部全屏面板。打开和关闭时只做 280–360ms 的位移与透明度变化，不使用弹跳动画。

## 7. 响应式

### 桌面端

- 最大内容宽度约 1560px。
- 上传页双栏，分析页固定侧栏。
- Bento 模块允许 2–3 列组合。

### 平板

- 上传页缩为 45/55 双栏或上下排列。
- 分析导航变成横向可滚动条。
- 证据抽屉占屏幕约 60%。

### 手机

- 上传页单列，先标题后上传卡片。
- 上传卡片高度降至约 470px，但保留轨道动画。
- 顶部操作收纳为一个操作菜单。
- 所有分析模块单列。
- 热力图允许横向滚动。
- 所有触控目标至少 44px。

## 8. 功能边界

本次只重做界面和交互，不修改：

- 物品、场景、音频任务识别逻辑。
- 分歧率、严重分歧率和混乱度计算方式。
- 原因汇总、规则冲突和标注员偏差算法。
- Excel、CSV、TSV 文件读取方式。
- 浏览器本地解析与不上传原始数据的隐私原则。
- Markdown 与 CSV 导出内容。

## 9. 验收标准

1. 上传页第一眼明显区别于普通后台。
2. 总览首屏无需滚动即可看到最高优先级结论。
3. 所有十类分析能力仍可访问。
4. 结论能够追溯到答案分布、人员和原因。
5. 桌面与手机端均无内容遮挡或不可点击区域。
6. 动画流畅，并支持减少动态效果。
7. 真实音频样例可以完成上传、分析、导航、证据展开和导出。
8. GitHub Pages 公共链接能够由未登录用户访问。
